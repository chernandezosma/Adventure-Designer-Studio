# Character

The main character of this such of games is the player himself, but it has in
common with other games" players , he will be ruled by a set of parameters like
life, stamina, magic level, etc.

## Character definition

This is the character's schema which rules it:

```json
{
  "character": [
    {
      "id": "<uint8_t>",
      "name": "<String> | max: 128",
      "descriptions": "<Texts> — see common-structures.md#decriptions-definition",
      "image": {
        "image": "<String> | Filename or string encoded",
        "avatar": "<String> | Filename or string encoded"
      },
      "state": "<uint8_t> — state ID from the States catalog below",
      "capacities": {
        "load": "<uint8_t>",
        "vitalities": {
          "life": "<uint8_t>",
          "stamina": "<uint8_t>",
          "sanity": "<uint8_t>"
        }
      },
      "affordance": "<affordance[]> — see item.md's Affordances definitions",
      "triggers": "<Triggers> — see common-structures.md#global-triggers"
    }
  ]
}
```

### Details

Several of the entries above require further explanation; these are detailed
below.

<font color="#C27AFF">id</font>: This is a unique value (`<uint8_t>`) for the
main character. It should be not modified and it will be autogenerated.

<font color="#C27AFF">name</font>: This is the character's name. This will be
shown every single time that the main character is named. Its maximum size is 20
characters.

<font color="#C27AFF">descriptions</font>: This is the group of extra texts
which will describe the character. See the
shared [Texts definition](common-structures.md#descriptions-definition) in
common-structures.md.

<font color="#C27AFF">image</font>: This is a group with two items, the main
character image, and its avatar. Both are two strings coding in Base64, and
stored in the JSON file.

<font color="#C27AFF">state</font>: `<uint8_t>` This is the main character's
state which indicate if there are any increase or decrease over the vitalities.
Those variations will be programmed by the game's creator which

<font color="#C27AFF">state</font>: `<uint8_t>` holding the value for the
character's single currently-active state. See [Main Character States](#States)

, looked up in the
[Conditions](#categories) catalog below and following the shared
[State Catalog Pattern](common-structures.md#states). A byte-sized field
supports up to 150 distinct authored states.

<font color="#C27AFF">capacities</font>:  It will be a static defined group of
numeric keys which indicate the values that gate stablish what the character can
physically and mentally do. See [Capacities](#capacities) below for the meaning
of each sub-field.

<font color="#C27AFF">affordance</font>: An array of `<affordance>` entries,
same shape as item.md's `affordance` field — each pairs an author-chosen
name with the trigger names it fires. Applies to any character (NPC or the
player) the IDE manages, not only the single "main character" this schema
otherwise describes.

<font color="#C27AFF">triggers</font>: Map from a character-applicable
global trigger id to an array of `EventId`s referencing entries in
[Event Schema](event.md#schema). See
[Global triggers](common-structures.md#global-triggers) for the character
ids (`on_talk`, `on_die`, `on_heal`, `on_hurt`) — an independent map from
Scene's and Item's own `triggers`.

### States

The main character state is a pre-defined conditions which will be applied on
the capacities group. In order to accomplish that we define the following
structure:

```json
{
  "state": {
    "id": "<uint8_t>",
    "text": "<Text>",
    "applied_on": "<uint8_t>",
    "ammount": "<uint8_t>",
    "duration": "<uint8_t>"
  }
}
```

#### Details

<font color="#C27AFF">id</font>: This is the state ID and this value, as always,
it will be unique. It is the reference to use the state in other structures.
<font color="#C27AFF">applied_on</font>: This is an `<uint8_t>` which indicate
the target of the application.

```
    7 6 5 4 3 2 1 0
    ---------------
    | | | | | | | |
    | | | | | | | |-> life (capacities.vitalities.life)
    | | | | | | |---> stamina (capacities.vitalities.stamina)
    | | | | | |-----> sanity (capacities.vitalities.sanity)
    | | | | |-------> load (capacities.load)
    | | | |---------> Reserved
    | | |-----------> Reserved
    | |-------------> Reserved
    |---------------> Reserved
```

<font color="#C27AFF">text</font>: This is the text that the game show when this
state will be active.

<font color="#C27AFF">ammount</font>: This is a positive or negative value, so
the value range is -127 to 128) and this will be applied on the `applied_on`
characteristic.

<font color="#C27AFF">duration</font>: This indicate how many turns will be
applied the `amount` value. This is applied using turn as unit because use a
timer will complicate the code, specially in the target 8 bit machines.

These last three items, will be translated as an event, but with modifications,
to be applied to specific value of an Object. Remember that event is applied
over an Object and not over its features.

|----|------------|------------------------------|--------|-----|----------------------------------|
| 10 | Confused   | capacities.vitalities.sanity | -10    | 3   | Randomizes directional commands. |

| 12 | Charmed    | capacities.vitalities.sanity | -30    | 6   | Restricts player choices .       |

Track how the surrounding environment has altered the character's immediate
physical condition.

| id | Name       | Applied to                 | Amount | Dur | Effect description                                         |
|----|------------|----------------------------|--------|-----|------------------------------------------------------------|
| 20 | Poisoned   | capacities.vitalities.life | -15    | 6   | Loses health during 3 turns until a cure with an antidote. |
| 21 | Envenomed  | capacities.vitalities.life | -15    | 6   | Loses health during 3 turns until a cure with an antidote. |

## Capacities
These resources are treated in a special way. The different values are stored in 
a `<uint8_t>` and we will apply this formula to get the normalized value: 

```
normalized = 1 + ((raw_value - min) / (max - min)) * 99
```

And these are the description and values for each item:

<font color="#C27AFF">load</font>: Indicate the load value and it range is from 0 to 49 in a byte.   
<font color="#C27AFF">Life</font>: Indicate the life value and it range is from 50 to 149 in a byte.  
<font color="#C27AFF">Stamina</font>: Indicate the stamina's value and it range is from 150 to 199 in a byte.  
<font color="#C27AFF">Sanity</font>: Indicate the mental sanity points and it range is from 200 to 255 in a byte.  

All values will be normalized and shown to the user in a range from 0 to 100.

If `capacities.vitalities.life` reaches 0, the player dies. When other capacities reach 0,
the player cannot perform any actions. 

In the future we will add new Capacities and the methods to set and get its
values.
